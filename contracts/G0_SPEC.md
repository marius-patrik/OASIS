Normative Rust surface: [`contracts/src/universal.rs`](src/universal.rs), built on [`contracts/src/lib.rs`](src/lib.rs). Neutral, game-free vectors: [`contracts/src/neutral.rs`](src/neutral.rs), tested by [`contracts/tests/g0_contract.rs`](tests/g0_contract.rs). **Major version 1** requires explicit adoption. Version 0 partial helper adapters are not production-full-game implementations, regardless of worker metadata.

## Contract decisions (apply identically to all sources)

1. **Native simulation authority.** `WorldSimulation` alone drives destination world, terrain/NPC/environmental logic, and reports `NativeGeometryBatch`. `CharacterController` uses its own originating controller/physics and queries the destination via `WorldPort`. The platform never selects a source game's solver for another game or synthesizes source mechanics.
2. **Stable ownership.** Platform `Id` is globally immutable. `NativeHandle` is strictly scoped by `ContextKey` and discarded on relocation/restart. Native authoritative state belongs to the originating world, entity, item or renderer module; `ContextManifest.owner_entity_id` optionally binds a single-entity context to its stable ID. **Unbound multi-entity** contexts may own multiple native slots; their trusted host MUST check `NativeHandle`→`Id` instance ownership against the context registry on snapshot/restore and every action, since a manifest alone cannot authenticate a slot. Only the owning source module can interpret opaque native bytes. Core persists typed attachments and provenance without reinterpreting native state.
3. **Capability/effects.** `ItemCapability` executes item-origin behavior and emits `InteractionRequest` with typed operation, immutable request ID, source tick and `AuthorityStamp`. A trusted platform authenticates/authorizes and fences each request *before* delivery; `AuthorizedEffectReceiver` is owned by the receiver, returns `EffectReceipt`, and commits through the trusted store exactly once. The receipt is NOT proof of authority: verify committed sequence, lease epoch and receiver revision against storage. Unknown target semantics return `ContractError::Unsupported` or `InteractionDisposition::Rejected`, never approximate a different game.
4. **Geometry/spatial frames.** Native shapes and source-defined typed contact materials are exported by the destination; original mover logic resolves collision. `FrameMap` supplies coordinates and units, including dimension embeddings if representable. Plane/mesh/custom geometry allow both 2D and 3D; unsupported projection fails explicitly. No universal physics replacement or engine-specific branch.
5. **Clock mapping.** Every module declares an *exact rational* tick rate; OASIS issues ordered `AuthoritativeTick { ClockStep, AuthorityStamp }` steps. Native tick counters are module-scoped and must be strictly increasing; world time and native time are not interchangeable. No client-authoritative ticks. Pause/oversampling mapping, input cutoff and replay determinism belong to lane B's scheduler; no implicit 60 Hz assumption.
6. **Lifecycle and isolation.** Native roles `initialize → activate → suspend → checkpoint/restore → activate → suspend → destroy`. Invalid transitions fail closed. Full native scene objects need not implement `Send`; workers use `IsolationMode::Process` and verified pinned artifact SHA-256. One process owns a single mutable-global game context; multiple native contexts must be *demonstrated* isolated. A separate process is **not** a security sandbox: lane B adds OS controls, quotas, kill/restart and input validation. Child SQL access is forbidden.
7. **Lossless native state.** `NativeCheckpoint` carries the owning context, scope, exact artifact hash, native codec/version, tick, revision, opaque native bytes and independently typed platform components. It is valid *only* against an exact manifest. Serialization completeness is **not** claimed by existence of a checkpoint, matching bytes, or a version tag: kill the source process, restore in another pinned worker and replay identical input, comparing all observable gameplay state and outputs including RNG, timers, live projectiles, NPCs, scripts and native camera. If original-save format omits state, extend the source-native bridge rather than platform inventing fields.
8. **Real rendering and cameras.** `NativeSceneRenderer` returns source-native `CameraState` and `NativeRenderPacket` with actual RGBA/BGRA pixels, optional finite normalized depth, alpha mode, camera/world space, z-order and frame identity. `NativeSurface.validate` rejects missing or malformed buffers. The platform must actually transport/compose/present native pixels, not merely `RenderContribution::SharedSurface` string handles or `CompositionPlan`. World and origin renderers may have distinct views; the viewer selects a camera owner explicitly.
9. **Deployment ABI.** These source-level v1 traits define semantics, not a stable cross-process wire encoding. Lane B must publish a versioned, bounded binary transport for every v1 operation and enforce process lifecycle, source artifact digest and data-size limits. Existing v0 worker handshake is useful foundation but cannot claim v1. Do not put `NativeContext` directly across process boundaries; IPC request/response types must encode the same `ContextKey` and authority.
10. **Independent conformance.** Each source adapter is independently obligated to run the **same** neutral fixture vectors (2D/3D, different clocks, foreign material queries, real pixel buffers, origin item effect handling, restart equivalence, independent contexts) without importing its counterpart. Current fixture tests prove only representation/envelope validation. Lane B owns real fixture-module executables and full conformance runner. Final cross-game tests in #7 **must not** influence adapter implementation.

## Context roles and concrete API ownership

| Interface/model | Owner | Required evidence |
|---|---|---|
| `ContextKey`, `ContextManifest`, `LifecyclePhase`, `NativeCheckpoint` | G0 contract / B worker; A storage | Different-context handles rejected, exact digest, lifecycle state machine, cold replay equivalence |
| `WorldSimulation`, `NativeGeometryBatch`, `WorldPort` | C/D destination source; B routing | Original world ticks; contact materials and native surface provenance; geometry queries |
| `CharacterController` | C/D source | Original movement/input, origin solver, multiple native contexts |
| `ItemCapability`, `AuthorizedEffectReceiver`, `EffectReceipt` | C/D source behavior; A authorization/storage | Authenticated receiver-owned idempotent effect and stale lease rejection |
| `AuthoritativeTick` | A admission / B scheduler | Distinct rational rates, ordered tick rejection, epoch fencing |
| `NativeSceneRenderer`, `NativeRenderPacket`, `NativeSurface` | C/D native renderer / B compositor | Actually rendered pixels and depth, native camera selection, composited visible client output |

## Migration instructions — no compatibility production path

**Lane A:** import v1 `NativeCheckpoint` and effect identities into versioned persistence/API. Accept opaque blobs only from authenticated contexts with registered exact artifact hash and legitimate lease. Introduce receiver-fenced idempotent effect application and cold restore checks. Avoid game-specific SQL and do not change these shared types from an A branch without a G0 PR.

**Lane B:** implement v1 worker protocol (separate handshake `contract_major=1`), bootstrap/activate/suspend/restore/destroy, context and artifact validation, bounded binary checkpoint and actual pixel transport. Upgrade host scheduler and native render path to v1 traits; preserve old partial tests only as tests, not a live production fallback. Build 2D and 3D synthetic modules **in separate crates** and share fixture vectors from `oasis_contracts::neutral`. Test authenticated effect forwarding with store integration rather than trusting a worker receipt.

**Lane C:** implement `WorldSimulation + CharacterController + ItemCapability + NativeSceneRenderer + AuthorizedEffectReceiver` in the pinned DOOM-native worker as applicable; isolate mutable-global contexts into distinct processes. Source render buffer must carry actual pixels. Full p_saveg/thinker/RNG/state-equivalence is a required gate; no original-game takeover by OASIS. Do not import or inspect lane D.

**Lane D:** implement identical v1 role interfaces using only the pinned Cave Story source and its reviewed bridge. Original `GameScene` lifecycle, `SharedGameState`, `BulletManager`, scripts, NPCs, graphics, RNG and timers require full lossless checkpoints, with two separate live contexts, not only movement/ammo persistence. Do not import or inspect lane C.

**Shared API change procedure:** post proposed interface delta and neutral failing vector on this PR or a fresh G0-owned PR; obtain review before cross-lane changes. B must add process-ABI tests, C and D must rerun independent source CI. No destructive changes to parallel lane files, no transition shims to conceal conformance gaps.

## G0 vs production verification

- Structural checks: `cargo test -p oasis-contracts --test g0_contract --locked`; `cargo test --workspace --lib --locked`; `cargo clippy --workspace --all-targets --locked -- -D warnings`.
- Source checks: native-source CI builds each pinned upstream at the pinned revision and runs its own adapter tests. These tests currently **do not** exercise the entire v1 contract.
- G0 exit: review/merge contracts, audited feasibility, licensing and requirements evidence, healthy CI, no cross-lane API ambiguity. Neither source engine is certified fully playable at G0.
- A/B/C/D exit: full executable source-owned conformance + per-lane proofs from #37, not an assertion about source metadata.
